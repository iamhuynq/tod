# P1 Plan: Data Foundation

Status: awaiting owner approval
Protocol: 1.2 (frozen)
Spec: plan v1.2 sections 7-8, 12

## Goal

Reliable, quality-checked, reproducible 1m candle data for the development period,
plus a running collector for prospective data.

## Scope

In: 1m klines (development period), quality checks, data snapshots, metadata DB,
DuckDB views, live 1m collector, daily `exchangeInfo` snapshots.
Out: aggTrades (P4b), order book (out of scope), holdout data (after P3), features (P2).

## Steps

| # | Step | Output |
|---|---|---|
| 1 | 1m kline downloader: monthly archives, SHA-256 verified, development months only, guarded by `holdout_guard` | `data/dev/raw/klines_1m/<SYMBOL>/` |
| 2 | Normalize to Parquet partitioned `symbol/year/month`; ms UTC timestamps; schema check | `data/dev/klines_1m/` |
| 3 | Quality checks per `(symbol, UTC day)`: bar count vs 1440, gaps, duplicates, non-monotonic keys, OHLC consistency (`low <= open,close <= high`), zero-volume share, halt detection (whole-day gaps and known delist ranges). Status `pass` / `warn` / `fail` | `data/dev/quality/klines_1m.parquet` |
| 4 | Metadata DB (SQLite + SQLAlchemy) with `data_snapshot` table. A snapshot = list of partitions + their SHA-256 + quality report hash; ID is content-derived so identical data gives the same ID | `data/metadata.sqlite`, `qrs snapshot create/show` |
| 5 | Run 1-4 on the 5 engineering symbols; review quality report | Report section |
| 6 | Extend to all 83 symbols that were ever monthly top-15 members, covering only their member months plus 180 days of warm-up | Report section |
| 7 | DuckDB views (no data copy): `klines_1m`, `klines_1d`, `universe_membership`, `quality` | `data/qrs.duckdb` |
| 8 | Live collector: every minute fetch closed 1m bars for the engineering symbols via REST (`/api/v3/klines`), idempotent upsert into hourly Parquet files, gap backfill on restart; daily `exchangeInfo` snapshot | `data/live/`, `qrs collect` |
| 9 | Schedule the collector (macOS `launchd` agent) and run 7 days | Collector log + gap report |
| 10 | Phase report with test output | `docs/phase-reports/P1.md` |

## Exit criteria (from plan section 12)

- Quality report exists for every `(symbol, day)` in scope; every `fail` is explained.
- A snapshot rebuilt from its ID reproduces identical file hashes.
- Live collector runs 7 days with no unexplained gaps.
- pytest, ruff, mypy pass.

## Tests

- Downloader refuses months after the development end (guard test).
- Quality checks on synthetic days: missing bars, duplicates, bad OHLC, halts.
- Snapshot ID is deterministic and changes when any partition changes.
- Collector: idempotent re-run produces no duplicates; backfill fills a simulated gap.

## Estimates

| Download, 83 symbols | ~2.5k files, ~8-15 GB raw zip, ~3-6 GB Parquet |
| Disk needed | ~25 GB free to be safe (raw zips can be pruned after verification) |

## Risks

| Risk | Mitigation |
|---|---|
| Laptop sleeps, collector misses data | Backfill from REST on restart (Binance serves recent 1m history); gaps logged |
| REST rate limits | 5 symbols x 1 request/min is far below limits; exponential backoff |
| Archive has missing months for some symbols | Recorded as `fail` days; no silent fill |

## Rollback

All outputs live under `data/` (git-ignored) and `data/metadata.sqlite`. Rollback =
delete the generated directories and the DB; code changes revert with git.
The collector `launchd` agent is removed with `launchctl unload` + deleting its plist.
